A genuine binary Microsoft Project file, used by `tests/test_mpp.py`.

| Format | OLE2 compound document, written by MS Project 14 (2010) |

It is committed rather than downloaded at test time so the suite has no network
dependency and the bytes under test cannot change underneath it.
`tests/test_mpp.py` checks the hash, so a corrupted or substituted fixture fails
loudly instead of quietly testing something else.

### Why a vendored file is necessary

Nothing can write `.mpp` — not MPXJ, not this project, not any library. It is
produced only by Microsoft Project itself. Every other format in the suite is
generated by the test that consumes it; this one cannot be, so a real file has
to come from somewhere and stay put.

The rest of `tests/test_mpp.py` uses MSPDI XML, which MPXJ also reads, to
cross-check MPXJ against this project's own pure-Python reader. That covers the
translation layer. This file covers the part that cross-check cannot reach: the
binary parser itself, on bytes that came out of the real application.
